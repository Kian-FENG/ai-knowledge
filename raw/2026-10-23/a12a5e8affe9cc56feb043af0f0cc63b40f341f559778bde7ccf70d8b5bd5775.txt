L21: # Claude Security now scans continuously and tracks fixes
L22: 
L23: Claude Security now keeps up with your repositories as code changes, tracks findings until they’re fixed, learns from the context your team adds, and connects to your tools through an API and MCP. Available in public beta for Claude Enterprise customers.

L34: Since 【9†Claude Security】 entered public beta in April, thousands of organizations have used it to find over a million vulnerabilities.
L35: Instead of waiting for someone to start a scan, Claude Security now keeps up with your repositories as your code changes, keeps track of which findings get fixed, and uses what your team tells it about your environment to decide what matters. Claude Security is powered by our full family of models, including Claude Mythos, with no Cyber Verification Program access required.
L36: The latest version of Claude Security is available today in public beta for Claude Enterprise customers. Organizations receive $25,000 in free usage credits each month, for two months. The offer applies to usage through December 31, 2026. You can view full terms in the 【10†Help Center†support.claude.com】.
L37: ## Continuous monitoring keeps up with your code
L38: 
L39: A scan captures one moment, and code changes every day. Teams told us they wanted coverage that stays current without anyone having to schedule it.
L40: Create a project, connect your repositories through the Claude GitHub app (including GitHub Enterprise Server) or with an access token from GitLab and other Git providers, and choose the branch and scope for each. Claude runs a deep baseline scan, then scans changes regularly based upon their risk and complexity, so your list of findings stays close to the current state of your code.
L41: A project can hold multiple repositories, so Claude can catch issues that live between services, like a backend that trusts input a client was supposed to validate.
L42: 
L43: 【11†Image: Claude Security UI†assets.claude.com】
L44: ## Findings are marked fixed when the fix ships
L45: 
L46: Most fixes happen outside the tool that found the issue. Claude Security checks open findings against the code that changed and marks them fixed when the fix lands, whether your team fixed it in Claude Code or in a separate process. If Claude Security finds the issue again later, the finding reopens automatically.
L47: 
L48: 【12†Image: Claude Security UI†assets.claude.com】
L49: ## Your team’s knowledge shapes the scan
L50: 
L51: Every environment has controls a scanner can’t see from the code alone. Teams wanted a way to tell Claude Security about those controls, and to look across services that depend on each other. Now, each project has a knowledge base where you can describe how your code is deployed, which security policies apply, and anything a new security engineer on your team would need to know.
L52: 
L53: 【13†Image: Claude Security UI†assets.claude.com】
L54: Claude Security also generates a threat model from your code that your team can review and edit. Subsequent scans use those threat models to decide what’s worth flagging. Added context also helps Claude Security skip risks your environment already handles.
L55: ## Severity and exploit paths for every finding
L56: 
L57: Each finding comes with a severity rating, judged against your project’s threat model, and an explanation of how an attacker could reach the vulnerable code, so teams can fix what’s actually reachable first. Findings can include a diagram of the attack path.
L58: 
L59: 【14†Image: Claude Security UI†assets.claude.com】
L60: ## Findings reach your tools, with controls for larger rollouts
L61: 
L62: The new API lets you integrate Claude Security into your existing workflows. You can list and read projects and findings, resolve or reopen findings, and create and manage projects and their repositories. Users can create a personal access token in Claude Security settings, and it can only see and change what the user can. Webhooks can also notify your systems when a new finding lands.
L63: Claude Security is also available as an MCP connector in 【15†Claude.ai†claude.ai】 and Claude Code. An engineer can pull up a finding, ask Claude about it, start the fix, and mark it resolved in the same session.
L64: 
L65: New role-based access controls let admins decide who can view projects, triage findings, and create projects. Organizations can open Claude Security to more teams that own the code without giving everyone access to create projects.
L66: ## Getting started
L67: 
L68: The latest version of 【16†Claude Security†claude.ai】 is available in public beta for Claude Enterprise customers starting today. Admins can enable it in the admin console and set who on their team can access it.
L69: 
L70: Use the 【17†Getting Started Guide†academy.claude.com】 to set up your first project, and visit the 【10†Help Center†support.claude.com】 for more details.
L71: Organizations receive $25,000 in free usage credits each month, for two months. The offer applies to usage through December 31, 2026. You can view full terms in the 【10†Help Center†support.claude.com】.
